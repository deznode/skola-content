# Ambiente Virtual i pip

Imajina bu é un trabadjadur ki ta faze txeu tipu di trabadju diferenti — un dia bu ta konsertá bisikleta, otu dia bu ta konsertá kanudu di iagu. Si bu mistura tudu ferramenta na un kaxa sô, bu ta kaba ku kunfundi kual ferramenta é pa kual trabadju — ou peor: un ferramenta di un trabadju pode danifika otu.

**Ambientis virtual** na Python é kumo tene un **kaxa di ferramenta separadu** pa kada projetu. Kada kaxa (ambienti) tene sô-l pakotis (bibliotékas) ki kel projetu spesífiku meste, na versons sertu — sen mistura ku pakotis di otu projetu, i sen risku di un projetu "kebra" otu pamodi versons diferenti.

Ma tene un diferénsa importanti ku un kaxa di ferramenta real: kaxa normal tene ferramenta fixu — ou martelu sta la, ou ka sta. Un ambienti virtual ta guarda más ki kel — el ta guarda **kual versan** di kada ferramenta. Projetu A pode meste `requests` versan 2.28, Projetu B kel mesmu pakotu `requests` má versan 2.31 — mesmu ferramenta, versons diferenti, kada un na se própriu kaxa. I un ambienti virtual ka é un ofisina interu separadu ku se própriu motor: el ka ta kopia Python interu pa kada projetu — el é sô un pasta di bibliotékas apontadu pa un interpretador Python, ki alges bez é kompartidu ku otus ambientis. I diferenti di un kaxa di ferramenta ki bu pode leba pa kualker lugar, un ambienti virtual sta gruda na se kaminhu exatu na disku: si bu move ou rinomia pasta di projetu, el ta kéba.

<SectionHeading variant="concept" seq={1}>Pamodi Ambientis Virtual É Esensial?</SectionHeading>

Sen ambiente virtual, tudu pakotu ki bu instala ta bai pa un lugar global — partilhadu pa TUDU bu projetus. Kel ta kria problemas sério:

```text
❌ SEN ambiente virtual:
┌──────────────────────────────────────┐
│ Python Global                        │
│                                      │
│ Projetu A presiza: requests 2.28     │
│ Projetu B presiza: requests 2.31     │
│                                      │
│ 💥 KONFLIKTU! Só un versan podi      │
│    sta instaladu di kada bez!         │
└──────────────────────────────────────┘

✅ KU ambiente virtual:
┌─────────────────┐  ┌─────────────────┐
│ Projetu A       │  │ Projetu B       │
│ .venv/          │  │ .venv/          │
│ requests 2.28   │  │ requests 2.31   │
│ flask 2.0       │  │ django 5.0      │
│                 │  │                 │
│ ✓ Izoladu!     │  │ ✓ Izoladu!     │
└─────────────────┘  └─────────────────┘
```

**Problemas reaís ki ta kontesi sen venv:**

- Bu atualiza un pakotu pa Projetu B i Projetu A ta kéba
- Bu ka sabe kual pakotis bu projetu realmenti presiza (tene 200 instaladu global!)
- Kuandu bu manda projetu pa kolega, el ka konsigi roda pamodi falta pakotis

<SectionHeading variant="concept" seq={2}>Fluxu Kompletu: Kria → Ativa → Instala → Freeze</SectionHeading>

:::callout{type=info}
Bu dja kria un `.venv` na **Lisan 02** — entun Pasu 1–2 li é un **rekapitulasan rápidu**. Kuze ki é nóvu nes lisan ben más baxu: `freeze`, partilha ku otu pesoa, i `.gitignore`.
:::

### Pasu 1: Kria Ambiente Virtual

```bash
# Navega pa bu pasta di projetu
cd meu_projetu

# Kria ambiente virtual (konvensan: .venv)
python -m venv .venv
```

Kel komandu ta kria un pasta `.venv/` ku un kópia izoladu di Python i pip.

### Pasu 2: Ativa Ambiente Virtual

```bash
# macOS / Linux
source .venv/bin/activate

# Windows (cmd)
.venv\Scripts\activate

# Windows (PowerShell)
.venv\Scripts\Activate.ps1
```

Kuandu ativadu, bu terminal ta mostra `(.venv)` na inísiu:

```bash
(.venv) $ python --version
Python 3.13.2
(.venv) $ pip list
Package    Version
---------- -------
pip        24.0
```

:::callout{type=tip}
Si bu ta uza VS Code, el ta deteta `.venv` automatikamenti i ta pidi pa selesioná kumo interpretador Python. Klika "Yes"!
:::

### Pasu 3: Instala Pakotis

```bash
# Gosi tudu ki bu instala ta bai SÓMENTI pa kel .venv
(.venv) $ pip install requests
(.venv) $ pip install flask
(.venv) $ pip install python-dotenv

# Verifika ki ta instaladu
(.venv) $ pip list
Package        Version
-------------- -------
certifi        2024.2.2
charset-normalizer 3.3.2
flask          3.0.2
requests       2.31.0
...
```

### Pasu 4: Jera requirements.txt

```bash
# "Freeze" tudu pakotu i ses versan pa un fixeru
(.venv) $ pip freeze > requirements.txt
```

Kel fixeru `requirements.txt` ta parsé ku kel li:

```text
certifi==2024.2.2
charset-normalizer==3.3.2
flask==3.0.2
requests==2.31.0
python-dotenv==1.0.1
```

### Pasu 5: Dezativa

```bash
# Kuandu bu akaba di trabadja
(.venv) $ deactivate
$ # Prompt volta pa normal -- bu sta fora di venv
```

<SectionHeading variant="concept" seq={3}>Partilha Projetu ku Otu Pesoa</SectionHeading>

Kuandu Ana kere roda bu projetu, el só presiza:

```bash
# 1. Klona ou kopia projetu
git clone https://github.com/nilton/gestor-notas.git
cd gestor-notas

# 2. Kria ses própriu ambiente virtual
python -m venv .venv

# 3. Ativa
source .venv/bin/activate  # (ó komandu Windows)

# 4. Instala tudu dependénsia a partir di requirements.txt
pip install -r requirements.txt

# 5. Pronto! Tudu pakotu instaladu ku versan serti
python main.py
```

:::callout{type=tip}
`pip install -r requirements.txt` ta ler kel fixeru i instala tudu pakotu listadu, ku versan exatu. É kumo un "lista di ferramenta" pa bu projetu — garantia ki tudu pesoa ta uza mesmu ferramenta, na mesmu versan.
:::

<SectionHeading variant="concept" seq={4}>.gitignore: Nunka Manda .venv pa Git!</SectionHeading>

Pasta `.venv/` tene miláris di fixeru (Python interu + pakotis). El é **spesífiku** pa kada komputador i **ka debe bai pa git**:

```bash
# .gitignore
.venv/
__pycache__/
*.pyc
.env
```

```bash
# Struktura ki ta bai pa git:
gestor_notas/
├── .gitignore           ✓ ta bai
├── requirements.txt     ✓ ta bai (lista di ferramenta)
├── main.py              ✓ ta bai
├── modulus/             ✓ ta bai
│   ├── __init__.py
│   └── estudanti.py
├── .venv/               ✗ KA ta bai (na .gitignore)
└── .env                 ✗ KA ta bai (segredus!)
```

<SectionHeading variant="concept" seq={5}>Erus Komun i Soluson</SectionHeading>

### Eru 1: "python: command not found"

```bash
# Tenta python3 en bez di python (macOS/Linux)
python3 -m venv .venv
source .venv/bin/activate
```

### Eru 2: "No module named venv"

```bash
# Linux: presiza instala venv separadu
sudo apt install python3-venv
python3 -m venv .venv
```

### Eru 3: Skedji di ativa .venv dipos di kria

```bash
# Senpri ativa antis di instala!
# Si bu instala sen ativa, pakotu ta bai pa global ❌
source .venv/bin/activate   # PRIMERU
pip install requests        # DIPOS
```

### Eru 4: PowerShell blokeia aktivasan (Windows)

```powershell
# Si da eru di "execution policy":
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
# Dipos tenta di nóvu:
.venv\Scripts\Activate.ps1
```

### Eru 5: requirements.txt sta fora di sinku

```bash
# Si bu instala pakotu nóvu, atualiza requirements.txt!
pip install beautifulsoup4
pip freeze > requirements.txt   # Re-jera fixeru
```

<SectionHeading variant="concept" seq={6}>Fluxu Rezmidu (Txeat Sheet)</SectionHeading>

```bash
# === PROJETU NÓVU ===
mkdir meu_projetu && cd meu_projetu
python -m venv .venv
source .venv/bin/activate      # (ó .venv\Scripts\activate na Windows)
pip install requests flask
pip freeze > requirements.txt
echo ".venv/" >> .gitignore

# === PROJETU ESISTENTI (klonadu di git) ===
cd projetu_esistenti
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# === KUANDU AKABA ===
deactivate
```
